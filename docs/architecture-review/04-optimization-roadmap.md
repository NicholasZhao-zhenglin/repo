# 04 · 后续路线（均未实施）

当前个人本地用途已经实现，下面是触发条件驱动的建议，不是遗留必做业务。

| 触发条件 | 建议工作 | 依据 | 验收条件 |
| --- | --- | --- | --- |
| 真实库导出等待明显 | 测量耗时和内存，再隔离压缩到 worker | [F01](03-engineering-findings.md#f01--主进程内进行图片和完整备份处理) | UI 可响应；故障不提交；备份跨版本可恢复 |
| 反复换图占用明显 | 可预览、可取消的无引用图片清理 | [F02](03-engineering-findings.md#f02--历史头像占用磁盘) | 当前库和上一版仍可读取；回收量可核对 |
| 明确要给他人分发 | Developer ID 签名与公证 | [F03](03-engineering-findings.md#f03--本地临时签名) | 带下载标记的发行包在干净 Mac 正常启动 |

无需为当前规模引入数据库或服务端。JSON 便于复制与恢复，现有串行写入适合单实例个人工具；当测得全量序列化成为瓶颈，再评估 SQLite。若改变备份格式，必须增加版本号、保留旧版读取、先导出完整旧库、验证迁移后角色和图片数量；失败可恢复旧目录，不就地破坏唯一副本。

未来验收使用合成数据与临时目录。没有当前测量基线，不承诺提升倍数或虚构容量数字。每次有实质改变，更新根目录三份文档、对应调用链和验证记录。
