# 03 · 工程边界与问题

基于 v1.0.0 源码观察和隔离桌面测试，未发现阻碍本轮个人本地使用的 P0/P1 功能缺陷。测试覆盖与限制见 [验收记录](evidence/verification.md)。优先级按用户的本地用途判断：P2 为未来需要额外验证或改进的边界，P3 为可选维护。

| 编号 | 优先级 | 当前边界 | 证据 / 状态 |
| --- | --- | --- | --- |
| F01 | P2 | 大库备份和图片处理可能短暂阻塞主进程 | 静态确认处理位置；未测容量阈值 |
| F02 | P3 | 替换或移除头像后，旧图片不自动清理 | 静态确认；当前为保留恢复能力的取舍 |
| F03 | P3 | 下载分发没有 Apple Developer ID 公证 | 打包配置确认；本机签名和启动已验收 |

## F01 · 主进程内进行图片和完整备份处理

位置：`electron/main.ts` 的图片处理器、`electron/store.ts/encodeBackup` 与 `inspectBackup`。JSON 序列化、gzip 和 nativeImage 解码会使用主进程执行时间；大量高分辨率头像时可能出现界面等待。已有单张 20 MB、像素数、输出尺寸、256 MB 解压内容限制。未进行真实规模压测，不声称已发生长期卡顿。

建议在用户实际遇到延迟时，先测典型角色库的导出耗时与峰值内存，再考虑 worker 或流式备份。验收应验证响应时间改善、输出可恢复、失败时不改变角色库，不能只测压缩函数速度。

## F02 · 历史头像占用磁盘

位置：`ArchiveStore.save/remove/importBackup`。旧图片未在每次提交后删除，确保 `.previous` 和当前数据仍能读取。反复换图可能累积未引用文件；没有测得泄漏速率或无限循环故障。

可选清理必须同时计算当前库与 `.previous` 的引用，并保留自动备份独立包含的图片。验收需先展示可回收空间，清理后测试当前详情、上一版回滚及完整备份恢复。当前不自动删除，避免未经验证破坏恢复链。

## F03 · 本地临时签名

位置：`scripts/package.mjs`，`codesign --force --deep --sign -`。本机验证和打包后二进制启动通过；从浏览器下载带 quarantine 属性的包可能触发 Gatekeeper 提示。README 已说明系统「仍要打开」入口，未关闭保护机制。

若将来改为面向他人持续分发，再取得开发者证书和公证，并在干净环境验证带下载标记的包。本次仅个人本机使用，不把证书采购或账号建设加入交付条件。
